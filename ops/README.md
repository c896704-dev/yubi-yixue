## 一条总原则

**先确认「这是环境问题还是代码问题」，再动手改。**

这份笔记里最贵的几条教训都来自同一个错误：把环境造成的假象当成了产品缺陷。
几个具体例子（详见各文件）：

- Node 的 `fetch` 在沙箱里报 `fetch failed`，`cause: ENOTFOUND` —— 是沙箱禁 DNS，
  而 `curl` 走代理所以能通。**同一台机器、同一个地址，两个客户端结论相反。**
- 浏览器面板隐藏时**不绘制 `will-change` 合成层**，截图返回空白 —— 是工具的问题，
  页面的 DOM 与计算样式全都正常。
- 本地 `npm run build` 出来的包比线上大 476KB —— 不是"部署漂移"，
  是根 `.env` 里的 `NODE_ENV=development` 让本地打出了 React 开发版。
  生产模式重建后 **SHA-256 与线上逐字节相同**。
- `npm audit` 同一台机器跑出 20 和 34 两个数 —— 是 npm 缓存陈旧（停在 5 天前的 advisory 快照）。

共同点：**在一个没有被固定的变量上做了比较。**
下结论之前先问一句：除了我要测的那个变量，还有什么是不一样的。
