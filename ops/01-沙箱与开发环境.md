# 01 · 沙箱与开发环境

这台 macOS 上跑命令时，外面套着一层 Seatbelt 沙箱（**每条命令单独套**，不是整个会话）。
它拦掉的东西不少，而且**失败信息长得像代码出错**，很容易误判。
这份文件把「撞到什么、怎么判断是环境问题、怎么绕」逐条记下来。

---

## 一、网络：只有一条通路

| 受限项 | 症状 | 判断 |
|--------|------|------|
| 原始 TCP（任意端口直连） | `Operation not permitted` | socket 层硬禁 |
| 外部 DNS | Node 的 `fetch` 报 `fetch failed`，`cause: ENOTFOUND` | 不是代码问题 |
| 到服务器的 22 端口 | ssh / scp / rsync / sshpass 全部连不上 | 要走终端面板（见下） |

**唯一能出网的方式是沙箱的过滤代理**（环境变量 `HTTPS_PROXY` 里那一串）。
所以会出现这个反直觉的现象：

```bash
# 同一个地址，两个客户端结论相反 —— 因为 curl 认代理，Node fetch 不认
curl -sI https://api.deepseek.com          # → 200
node -e "fetch('https://api.deepseek.com')" # → fetch failed (ENOTFOUND)
```

> **别在沙箱里用 Node 调上游，然后得出「接口挂了」。**
> 要验证 AI 上游、外部 API，**到服务器上去跑**（那里没有这层限制），
> 或者把结论标注成「沙箱内不可验证」。

被拒的连接有时会在工具输出里带一个 `<sandbox_violations>` 块说明原因。
在 auto 模式下，把需要的域名写进 `allowed_domains` 再跑一次通常就通了。

## 二、端口与进程

| 受限项 | 症状 | 绕行 |
|--------|------|------|
| 绑定本地端口 | `listen EPERM: operation not permitted 0.0.0.0:3999` | 起不了本地服务 → 见下 |
| `ps aux` | `operation not permitted: ps` | 用 `lsof -nP -iTCP:<port> -sTCP:LISTEN` 查监听 |
| `open` / `osascript` | `-10822` / `-54` / `LSOpenURLsWithRole() failed` | 这是沙箱拦的，别重试；把命令交给用户自己跑 |
| `127.0.0.1` 的非代理端口 | 连不上（本地 dev server 也打不到） | — |

**起不了本地服务时怎么验证服务端代码**：不要依赖 HTTP 层，直接**调用真实的处理逻辑**。

```js
// 直接 import 真实模块，喂真实数据 —— 绕过网络与端口，测的仍是真代码
const svc = await import('./server/services/ai-service.js')
const r = await svc.callTextModel('只回复两个字：收到', apiKey)
```

如果需要测 Express 路由本身，可以构造假的 `req`/`res` 直接调用 handler，
或者把 `.env` 读进来后 `import` 路由模块取 `router.stack`——但更省事的做法是**到服务器上跑**。

## 三、PTY 与 SSH

```
Failed to get a pseudo terminal: Operation not permitted
```

沙箱里 `ssh` 拿不到 pty。（注：能连上的情况下，`ssh -T` 之类不需要 pty 的用法仍可能失败在这里。）

**这个失败分两层，诊断时先分清是哪一层**——两层的绕法不同：

| 报错 | 拦在哪 | 含义 |
|------|--------|------|
| `Failed to get a pseudo terminal: Operation not permitted` | pty 层 | sshpass 靠 pty 喂密码，pty 被拦 → 连都没连上 |
| `Operation not permitted`（python socket 连 22 端口） | socket 层 | TCP 直连也被拦，ssh 系全家不可能通 |

```bash
# 先测 TCP 通不通，把「网络被拦」和「pty 被拦」分开
python3 -c "
import socket
s=socket.socket(); s.settimeout(6)
try: s.connect(('115.190.56.178',22)); print('TCP OPEN')
except Exception as e: print('TCP BLOCKED:', e)
"
```

> **同一条 ssh 命令，不同时间结果可能不同**——2026-09-08 那轮部署全程用
> `sshpass -p … ssh …` 从 Bash 直连成功（pull / build / pm2 restart 都拿到了真实输出），
> 而 2026-10-05 再跑就整体不通。**可用性取决于当时的沙箱/权限状态，不是稳定通道。**
> 判断方法就是上面那两行：TCP 与 pty 各测一次；不要因为「上次能用」就把这次失败当成代码问题。

**绕行：用终端面板。** 终端面板在**用户的登录 shell** 里跑，不受这层沙箱限制，
而且用户能看见——所以 ssh / rsync / scp 一律走它。

但终端面板自己有几条脾气：

| 脾气 | 说明 |
|------|------|
| **拒绝非 ASCII 命令** | 中文注释、中文路径一律不行。要删中文文件名用通配符：`rm -f ./*.docx` |
| 拒绝 zsh 的 `$~x` / `${(flags)x}` 形式 | 用大括号或普通写法 |
| 拒绝括号组 | `echo "(none)"` 会触发告警（zsh 的 glob 限定符语义），**去掉括号**写 `echo NONE` |
| 拒绝 `eval` / `.` / `source` / `<<<` 等 | 复杂脚本改成 **scp 一个脚本文件过去再执行** |

**推荐姿势**：命令长或含中文时，本地写成脚本 → `scp` 到服务器 `/tmp/` → ssh 执行 → 删掉。
比在命令行里跟引号搏斗可靠得多。

## 四、git

| 现象 | 原因 | 解法 |
|------|------|------|
| `Connection closed by UNKNOWN port 65535` / `nc: SOCKS error 2` | 走 SSH 推（22 端口被封） | 改用 HTTPS |
| `Failed to connect to 127.0.0.1 port 7897` | **git config 里指向用户自己的代理**（如 clash），沙箱里连不上 | 显式覆盖：`git -c http.proxy="$HTTPS_PROXY" ...` |
| `LibreSSL SSL_connect: SSL_ERROR_SYSCALL` | 代理/网络到 GitHub 断流，**沙箱内外都可能出现** | 过一会儿重试；沙箱里不行就在**终端面板**里重试 |
| `(eval):14: unmatched "` 提交失败 | 中文多行提交信息塞进 `-m "$(cat <<'EOF' … EOF)"` | 改走 stdin：`git commit -F - <<'MSG' … MSG`（本次实测一次成功） |

可用的推送写法（注意要覆盖代理，否则会去连用户自己那个）：

```bash
git -c http.proxy="$HTTPS_PROXY" -c https.proxy="$HTTPS_PROXY" \
  push "https://<PAT>@github.com/<owner>/<repo>.git" main
```

> GitHub 的连通性是**时好时坏**的，2026-10-05 那天沙箱和用户机器同时连不上，
> 过一阵又都恢复了。**推不上去不是代码问题，别去改代码。** 提交留在本地，网络好了再推。

## 五、文件系统与其它

- **写权限是白名单**。能写的是项目目录、`~/.claude`（部分子目录被排除）、`$TMPDIR` 等。
  往白名单外写会失败——**这是沙箱，不是磁盘满了**。
- **临时文件一律用 `$TMPDIR`**，不要写 `/tmp`。
- **macOS 上没有 `timeout` 命令**。用 `timeout 5 cmd && echo OPEN || echo BLOCKED` 探测端口
  会**全部误报 BLOCKED**——失败原因是 command not found，不是端口被封。
  探测端口请用 python 的 socket + settimeout。

```bash
# 别这样（timeout 不存在，结论全是假的）
timeout 3 nc -z host 22 && echo OPEN || echo BLOCKED

# 这样
python3 -c "
import socket
s=socket.socket(); s.settimeout(3)
try: s.connect(('host',22)); print('OPEN')
except Exception as e: print('BLOCKED:', e)
"
```

## 六、一句话

**碰到 `Operation not permitted` / `EPERM` / `ENOTFOUND` 这类字样，先当成环境限制处理，
不要当成代码 bug。** 判断方法：换一个不受该限制的通道（终端面板、服务器、curl）再试一次，
看结论是否相反。相反 → 是环境；一致 → 才轮到怀疑代码。
