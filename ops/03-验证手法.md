# 03 · 验证手法

> **改完不等于改对。** 这份文件记的是「怎么证明它真的生效了」——
> 每一种介质（页面 / 打印 / Word / 服务端）各有各的证法，也各有各的假象。

---

## 零、最重要的一条：别看状态码，看内容

这个站的 Express 有 `app.get('*')` 兜底：**任何找不到的路径都返回 `index.html` + HTTP 200**
（即审查报告里记的「软 404」）。所以「200」什么都证明不了。

实例——移除两个公开的设计稿页面后：

```
/design-demo.html    HTTP 200   1502 字节   ← 兜底页（= 站点首页），说明文件没了
/migrate.html        HTTP 200   4949 字节   ← 真文件还在
```

**判断方式是内容字节数 / 标题 / 关键字符串**，不是状态码。

## 一、前端：在浏览器里量，不要靠看

优先用文本工具而不是截图：

| 目的 | 做法 |
|------|------|
| 结构对不对 | `read_page` / `get_page_text`（可访问性树） |
| 样式对不对 | `javascript_tool` 读 `getComputedStyle`，**把数值打出来** |
| 有没有报错 | `read_console_messages` |
| 接口对不对 | `read_network_requests` |
| 布局对不对 | 量 `getBoundingClientRect()` 的宽高与位置 |

**「看起来没问题」不算验证。** 例如「表格有没有样式」要问的是
`getComputedStyle(td).borderBottomWidth` 和 `padding` 的值，而不是截图上像不像表格。

改完先确认改动生效了再往下测：

```js
// 确认新规则真的进了计算样式
getComputedStyle(document.querySelector('.report')).fontSize   // → '16px'
```

## 二、打印 / 存 PDF：把 print 规则摘出来当屏幕样式用

浏览器面板**没有 print media 模拟**，`@media print` 在屏幕上看不到效果。
可用做法：遍历 CSSOM，把 print 媒体块里的规则**原样摘出来**追加成一条普通样式表。

```js
(() => {
  document.getElementById('__print_emul')?.remove()
  let css = ''
  for (const sheet of document.styleSheets) {
    let rules; try { rules = sheet.cssRules } catch { continue }   // 跨域表读不到，跳过
    for (const r of rules) {
      if (r.type === CSSRule.MEDIA_RULE && r.conditionText === 'print') {
        css += [...r.cssRules].map(x => x.cssText).join('\n') + '\n'
      }
    }
  }
  const el = document.createElement('style')
  el.id = '__print_emul'
  el.textContent = css
  document.head.appendChild(el)        // 追加到最后 → 层叠顺序与真实打印一致
  document.querySelectorAll('.report-view details').forEach(d => d.open = true)  // 模拟 beforeprint
})()
```

⚠️ **不要用 `textContent.includes('@media print')` 去找样式表** ——
代码注释里提到这几个字就会被误匹配。我第一次就抓错了表，白跑一轮。**必须走 CSSOM。**

测完记得 `document.getElementById('__print_emul')?.remove()` 还原。

**视口也要对**：A4 页面盒约 794px 宽。用 `resize_window` 设成 794×1123 再量，
否则你看到的是屏幕宽度下的排版，不是纸面排版。

> `@page` 的页边距在屏幕模拟里不生效，所以分页位置只能近似。真要确认分页，
> 老实点一次「打印报告 / 存 PDF」看预览。

## 三、Word 导出：截住 Blob、手解 docx

导出走的是 `URL.createObjectURL` + 触发下载，所以**钩住这两处**就能拿到文件内容，不用真下载：

```js
window.__docxBlob = null
const origCreate = URL.createObjectURL.bind(URL)
URL.createObjectURL = b => {
  if (b instanceof Blob && b.type.includes('openxml')) window.__docxBlob = b
  return origCreate(b)
}
HTMLAnchorElement.prototype.click = function () {}   // 别真下载
// …然后点「导出 Word 报告」，等 window.__docxBlob 有值
```

`.docx` 就是个 ZIP。浏览器内置 `DecompressionStream`，不用装库：

```js
const buf = new Uint8Array(await window.__docxBlob.arrayBuffer())
const dv = new DataView(buf.buffer)
// 1) 从尾部找中央目录签名 0x06054b50，遍历条目拿 {name, comp, csize, lho}
// 2) 从 local header 之后取该条目的压缩数据
// 3) comp===0 直接用；否则 new Blob([raw]).stream().pipeThrough(new DecompressionStream('deflate-raw'))
// 4) 读 word/document.xml，把 </w:p> 换成换行再剥标签 → 就是全文
```

**要核对的是**：章节标题与序号是否与屏幕一致、AI 章节有没有标题、附录位置对不对。
（本项目曾出现过 Word 与屏幕章节完全不同步的问题，就是这么查出来的。）

## 四、服务端 / AI：到服务器上去跑

沙箱连不上外网上游（见 01），所以**验证 AI、验证真实网络行为一律在服务器上做**。
把验证脚本 scp 过去执行，比在本地跟代理搏斗可靠得多：

```bash
# 本地写 _verify.mjs（读 .env、import 真实模块、调真实上游、打印结果）
scp _verify.mjs root@<host>:/tmp/
ssh root@<host> 'cd /var/www/yubi-yixue && node /tmp/_verify.mjs; rm -f /tmp/_verify.mjs'
```

脚本要**调用项目自己的模块**（`import './server/services/ai-service.js'`），
而不是另写一份等价逻辑——否则测的是你的复制品，不是真代码。

接口层面用 `curl` 打生产，但记住配合「基线」才有意义：

```bash
# 上线前后跑同样的命令，对比输出
curl -s -w '|%{http_code}' -X POST -H 'Content-Type: application/json' \
  -d '{}' https://yubiyixue.xyz/api/analyze/ai-report
# 修复前：500 {"error":"AI 报告生成失败，请稍后重试"}
# 修复后：400 {"error":"缺少风水分析数据"}
```

## 五、验证「AI 输入串一个字都没变」

改模板函数时，**肉眼 diff 查不出一字之差**。用「取旧版本 → 抽全部字面量 → 多重集比对」：

```python
import io, re, subprocess
from collections import Counter

old = subprocess.run(['git','show','HEAD:src/utils/analysis.ts'],
                     capture_output=True, text=True).stdout
new = io.open('src/utils/analysis.ts', encoding='utf-8').read()

LIT = re.compile(r"`(?:[^`\\]|\\.)*`|'(?:[^'\\]|\\.)*'", re.S)
missing = Counter(m.group(0) for m in LIT.finditer(old)) \
        - Counter(m.group(0) for m in LIT.finditer(new))
print('旧版字面量缺失:', dict(missing) or '无 ✅')
```

**这条抓到过一处真实漂移**：重写时把「不可忽视**之**偏枯」写成了「不可忽视**的**偏枯」，
差一个字，而那是要喂给模型的上下文。**只有多重集比对能发现它。**

## 六、浏览器自动化的坑

| 现象 | 真因 | 绕法 |
|------|------|------|
| **截图一片空白** | 隐藏状态下 pane **不绘制 `will-change` 合成层**——DOM 与计算样式全都正常 | 先把合成层关掉再截：`document.querySelectorAll('div').forEach(d=>{if(d.style.willChange) d.style.willChange='auto'})` |
| 截图首帧空白，第二次才有 | 绘制延迟 | 同一位置**再截一次** |
| 脚本跑一半没了返回值 | 脚本里调了 `location.reload()`，刷新把脚本执行截断了 | 刷新**单独一次调用**，别写在业务脚本里 |
| `behavior:'smooth'` 滚动完全不推进 | 隐藏 pane 里 rAF 被节流 | 验证跳转用 `behavior:'instant'`，然后**复算偏移量** |
| `scrollIntoView()` 没反应 | 本项目实测无效（原因未定） | 改用 `window.scrollTo` 算绝对偏移 |
| `window.scrollTo` 也没反应 | 页面用了自定义滚动容器 | 先看 `document.scrollingElement`，或直接设 `scrollTop` |
| 越测越乱、结论互相矛盾 | **多个审查员共用一个浏览器配置**，`localStorage` 里带着别人的登录态 | 「要不要登录」这类结论**一律用不带 token 的 curl 复核** |

最后一条尤其阴——曾因此得出「AI 免费免登录」的错误结论，
而实际上 `server/routes/ai.js` 整条路由都挂了 `authMiddleware`。

## 七、一条格式

验证结论写成**「改前 X → 改后 Y」**，并附上你怎么量的。
「已验证」这三个字没有信息量，**具体数值才有**。
